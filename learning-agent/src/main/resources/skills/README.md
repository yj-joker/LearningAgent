# 内置 Skill 文件约定

- 每个技能放在 `skills/<name>/SKILL.md`，目录名必须与文件中的 `name` 一致。
- 使用 UTF-8；文件头以两行 `---` 包围 YAML 元数据，后面是非空 Markdown 正文。
- 第一阶段只支持 `name`、`description`、`metadata` 三个顶层字段，不静默忽略其他选项。
- `name` 为 1–64 个小写字母、数字或单个连接符，不能以连接符开头或结尾。
- `description` 不超过 1024 个字符；`metadata` 使用字符串键值，必须包含带引号的 `version`。
- `version` 为 1–64 个字符，以字母或数字开头，可包含点、下划线、加号和连接符。修改正文时同步更新版本。
- 单文件最多 64 KiB，最多注册 64 个技能；重复名称、错误格式或超限都会阻止启动，不会静默覆盖或截断。
- 应用启动时读取文件并建立只读快照；修改文件需要重新构建、启动，本阶段没有热更新。
- `SkillRegistry.listSkills()` 只返回名称、用途、版本；`getRequiredSkill(name)` 才返回完整正文。
- 不接受用户上传、任意路径、网络地址，不执行文件内的代码或脚本。
- 第二阶段主模型先看到索引，再通过 `load_skill(name, version)` 激活正文；没有加载时不发送正文。
- 加载工具只返回简短回执，正文在系统上下文中保留一份；不会进入未来对话历史，不会被普通工具结果截断。
- 一次任务默认最多激活 3 个技能、12000 个正文字符；总请求还受原上下文安全水位限制。
- 审批检查点保存已加载名称、版本和内容指纹；恢复时若内容变化或技能被删除，停止任务而不静默替换。

`learning-plan-draft` 只是用于验证格式的内置草案示例，不会保存正式学习计划。

`learning-teaching` 用于围绕长期计划当前步骤进行讲解、独立练习和点评；它只能提出掌握建议，不能直接确认步骤。
